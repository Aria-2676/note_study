## 0. 主线变更说明（2026-10-22）

上一版路线图把 v6 定义为「架构拆包 · 核心 + 拓展」，写的是：
"拓展包以独立 asset 包形式存放，运行时动态加载，热插拔"、"核心包控制在 2MB 以内"。

**这些前提已被实测推翻**（详见 `docs/INDEX.md` 的「已证伪的断言」）：
Flutter release 把 Dart AOT 成机器码，不存在运行时加载 Dart 代码的机制；
`libflutter.so` 一项就是 12MB，2MB 物理上不可能。

所以 v6 的主线改为：**平台化重写**——一个轻主包 + 可安装的插件，
插件用 WebView 承载页面、用数据插槽扩展主界面、用事件钩子参与业务。
完整论证见 `docs/platform-decision.md`。

## 2. v6.0.0 ｜ 平台化改造（一个版本，内部分 7 步）

主包整体一起做，下面是**动手顺序**，不是分批发布。

| 步 | 做什么 | 完成时的验证点 |
|---|---|---|
| 0 | **接口骨架**：插槽 / 钩子 / 货币框架 / 入口注册，只写接口与空实现 | 后续代码都照接口写，不各写各的 |
| 1 | 数据层新 schema（删三张旧迁移 mixin、`dbVersion` 归零、定 `plg_` 前缀规范） | 表能建、能读写 |
| 2 | 新任务页 + 新导航（**先用假数据**） | 界面手感对不对 |
| 3 | 接真数据 + 插槽生效 | 日期/徽章/标记真的会变 |
| 4 | 插件运行时 + 空货架（索引/下载/校验/安装/卸载） | 能装掉一个假插件 |
| 5 | **第一个货币插件：能量** | 钩子→发币→插件表→卸载，全链路通 |
| 6 | 逐个把旧模块改造成插件（小游戏 → 番茄钟 → 统计 → …） | — |

**第 5 步是真正的验收点**：能量插件跑通，整个插件机制才算成立。

## 3. v6.x ｜ 插件逐个上线

每个插件独立版本、独立更新，不牵动主包。顺序按"依赖最少、验证价值最高"排：

小游戏（已具备完整链路，拿来验证运行时）→ 主题包 → 番茄钟（验证计时引擎）→
统计（验证只读数据与图表）→ 商城 → 积分 → 刮刮乐（可随时舍弃）→ 记账

## 6. 已评估不做（决策留档）

- **Flutter 运行时加载 Dart 代码**：不存在这条路。见 §0
- **换栈到 React Native**：RN + Re.Pack 确实能同时做到"按需装 + 原生观感"，
  但代价是重写 3.4 万行 + 替换构建链（Re.Pack 替换 Metro）+ 长期维护成本，
  而收益只落在"观感"与"UI 复用"两项上。权衡见 `docs/platform-decision.md` §4/§5
- **APK 二进制差分（BSDiff/Courgette）**：Android 10+ SELinux 禁止自读 base.apk；
  Flutter AOT 机器码小改也整体重排，压缩率不稳
- **资源/游戏包文件级增量**：现均 1MB 级，增量不抵成本；等素材包超 10MB 再评估
